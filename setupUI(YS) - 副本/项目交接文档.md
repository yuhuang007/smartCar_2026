## 1. 项目背景

- **比赛**：第二十一届全国大学生智能汽车竞赛 —— 人工智能模型组
- **平台**：X-01 板卡（RK3588，含 3 个 NPU 核心）+ X-Verse AR 引擎（官方提供的 C++ 编译程序，跑一个 AR 仿真赛道）
- **工程**：`setupUI(YS)`，本质是"感知（检测+分割）→ 决策（巡线+避让+任务）→ 控制（驱动虚拟车）"的自动驾驶闭环
- **开发者定位**：编程小白，需要清晰解释 + 可直接跑的代码
- **调试方式**：代码在 Windows 上编辑，通过 `scp` 传到板卡，在板卡上 `python3 main_control.py` 运行

### 仿真机制要点
- AR 引擎渲染一个第一人称贴地视角的仿真赛道，画面通过共享内存 / HTTP 流输出
- 画面里有一辆**虚拟车**（画面主体视角就是它），通过网页 WASD 或 UDP:9005 控制
- 赛道是**蓝色发光箭头（人字形/V形）铺成的路面**，箭头指向前进方向
- 赛道上有其他**移动的车（出租车）、行人**作为障碍，还有**金币**（沿途收集）
- 还有红绿灯、路牌等任务元素

## 4. 核心协议：UDP 9005 虚拟车控制（★已抓包破解）

官方从网页删除了协议文档，通过 `sudo tcpdump -i any -A -n 'udp port 9005'` + 网页按 W 抓包确认真实格式：

```json
{
  "type": "robot_position",
  "is_sim": true,
  "pos": [x, y, z],
  "euler": [pitch, yaw, roll],
  "seq": 递增整数,
  "timestamp": time.time()
}
```

**关键点**：
- `pos` 是 **[x, y, z] 绝对坐标数组**（不是增量）
- `euler` 是 **[pitch, yaw, roll]**，注意 **yaw 在中间 index=1**
- `seq` 每帧递增；`timestamp` 用 `time.time()`
- **系统默认初始化位置是原点 (0,0,0)，yaw=0**（网页确认）

### 运动模型（`drive()` 方法，已验证方向正确）
```python
steering_delta = plan_offset * turn_rate * 2   # 偏移→转向
yaw += steering_delta; yaw %= 360
speed = max_speed * speed_ratio
x += speed * sin(radians(yaw))   # yaw=0 时沿 +Z 前进
z += speed * cos(radians(yaw))
```
- `turn_rate=5.0`，`max_speed=0.05`
- 提供接口：`drive(offset, speed_ratio)` / `stop()` / `turn_left(deg)` / `turn_right(deg)` / `close()`

> **`_build_payload()` 已按真实格式写好，不要再改格式。**

## 5. 导航方案演进（★踩坑记录，避免重复走弯路）

这是本项目最关键的经验，按时间顺序：

### ❌ 方案一：语义分割（pp_liteseg.rknn）
- **结果**：`seg=0.000` 永远失效。分割模型对这个 AR 仿真赛道**没有有效输出**（赛道类别 ID 对不上）
- **结论**：分割这条路对本赛道基本走不通，除非重新定位模型输出类别

### ❌ 方案二：边缘检测（Canny + 霍夫）
- **结果**：蓝色箭头图案在边缘检测下产生**一堆交叉乱线**（19~23 条），当车道线算 → 偏移错乱 → 车冲出地图
- **结论**：边缘检测在这种密集图案赛道上不可靠，只保留作最后回退

### ✅ 方案三：蓝色箭头 HSV 颜色分割（当前主导航）
- **核心洞察**：赛道是蓝色发光路面，蓝色在画面里极其独特，HSV 分割最稳
- **踩坑修正历程**：
  1. 初版用"近/远两带 + 平均值质心" → 绿点落到左下角（底部近带抓到角落杂色蓝，平均值被离群点带偏）
  2. **修正**：ROI 改成画面**中下部 0.40~1.0**（贴地视角下赛道在中部，底部车头下方不是赛道）
  3. **修正**：平均值 → **中位数**（对角落零散杂色不敏感，稳稳落在赛道主带）
- **当前结果**：✅ **绿点已准确贴在蓝色赛道上，px 检测量数万，导航感知成功**

### ✅ 方案四：赛道丢失主动恢复（★最新修复，解决"冲出地图"）
- **背景**：绿点准了，但车照样乱跑、冲出地图、不回赛道。**加 `[VCar]` 每帧诊断日志**后一举定位：
  - `arrow_valid=True` 时：`yaw` 在变、`x/z` 在动、`base` 偏移从 -0.15 慢慢收敛到 -0.05 → **控制链路完全正常，转向方向正确，巡线在把赛道拉回中心**（洗清了"引擎不理会 UDP"的嫌疑）
  - `arrow_valid=False` 时：旧代码回退 PathPlanner 返回 `base=+0.000` → `final=0` → `yaw` 卡死不变 → **车一路直行冲出地图，永不回头**
- **病根**：只要蓝色赛道跑出摄像头视野，程序就让车直走 → 越走越偏 → 出图。
- **修复**：丢失时**不再直走**，改为朝"最后一次看到赛道的方向"强力打方向（`base = sign(last_offset) × arrow_lost_recover_gain`）把赛道转回视野，同时减速（`arrow_lost_speed`）；正前方丢失无历史方向时按 `arrow_lost_default_dir` 默认搜索方向。
- **验证方法**：看 `arrow_valid=False` 的日志行，`base` 应为 ±0.4、`yaw` 应持续变化（车在打方向找赛道），而非以前的 `base=0 / yaw d+0.0`。

### 关键几何认知
- 车**初始不在赛道上**，停在赛道旁空地（画面底部是灰/彩虹地面，不是蓝色）
- 用户确认：**蓝带 = 赛道路面本身**，车应开在蓝带中心；弯道多，蓝带时横时纵
- 需要：先转向开上赛道 → 再沿蓝带巡线

## 6. 当前系统工作流程（main_control.py 主循环）

```
每帧:
1. 读取 AR 视频帧
2. 目标检测（InferWrap）→ boxes, classes, scores
3. 语义分割（SegWrap）→ seg_mask（当前无效，seg=0.000）
4. 【主导航】ArrowNavigator.navigate(frame)
   → arrow_offset, arrow_vis, arrow_valid, arrow_info
5. 边缘检测（回退用）
6. 确定 base_offset:
   - arrow_valid → base_offset = arrow_offset × arrow_steer_gain，speed=1.0
   - 否则（赛道丢失）→ 不直走！base = sign(last_offset) × arrow_lost_recover_gain（朝最后方向转回赛道）+ 减速
7. 避让 task_avoid_person() → avoid_offset, speed_ratio
8. 金币 detect_coins() → coin_offset（仅无避让时）
9. 红绿灯/路牌任务（按圈数）
10. 决策融合: final_offset = base_offset + avoid_offset + coin_offset（限幅±0.5）
11. 驱动虚拟车:
    - 启动对准阶段（_startup_turned < 目标）→ 原地转向找赛道
    - speed_ratio<=0 → vcar.stop()
    - 否则 → vcar.drive(final_offset, speed_ratio)
12. 显示三路面板: Detection | Arrow Nav | Edge
```

### 决策融合公式（核心架构）
```
final_offset = base_offset(箭头巡线) + avoid_offset(避让) + coin_offset(金币)
```
> **★最重要的架构点**：虚拟车转向**只由 final_offset 驱动**。所有决策（避让、金币）必须叠加进偏移量才生效，光画框不影响行为。

## 7. ArrowNavigator 导航器（当前主力，stream_seg_test.py）

```python
def navigate(self, frame):
    # 1. HSV 分割蓝色 mask + 形态学去噪
    # 2. ROI = 画面中下部 0.40~1.0
    # 3. valid = ROI内蓝色像素 >= min_pixels(80)
    # 4. cx = 中位数(xs)  # 关键：中位数抗离群
    #    raw_offset = cx/w - 0.5
    # 5. 平滑: offset = last*0.4 + raw*0.6
    # 6. 可视化: 逐行绿点(赛道走向) + 红色目标线 + "ARROW off=x OK/LOST px=N"
    return offset, vis, valid, info
```
- HSV 范围：lower=(85,50,80)，upper=(125,255,255)
- 输出 offset ∈ [-0.5, +0.5]，正=右，负=左

## 8. 避让逻辑（task_avoid_person，★刚重构）

### 重构前的三个致命问题
1. 避让方向和赛道方向打架（赛道在左、障碍也在左，往右避=出赛道）
2. 停车太晚（框底82%才停）→ 撞车
3. 避让力度太猛（gain=0.35）→ 顶出赛道
4. 远处/侧方目标乱触发

### 重构后策略（障碍都在赛道上，不能猛打方向出赛道）
```
过滤: 框太小(远) / 框底太靠上(远) / 中心偏移>0.28(侧方没挡路) → 全部忽略
决策(只对挡正前方的最近障碍):
  - bottom_ratio >= 0.62(很近) → 停车 speed=0，不打方向(avoid_offset=0)，稳在赛道等它走
  - 否则(中距离)             → 减速 speed=0.4 + 轻微避让(gain=0.15)
```
- 显示 `ACTION: STOP / AVOID R / AVOID L`

### 金币吸引（detect_coins）
- 仅吃**道路内**金币：横向偏移 ≤ 0.35 且 y > 0.4
- 道路外/太远不追；有避让时不吃
- 目标金币绿框高亮
- `coin_offset = cx_norm × coin_gain × 2.0`

### ★ `[VCar]` 诊断日志（最强调试利器）


看点：mode（STARTUP/STOP/DRIVE）、base/avoid/coin/final 偏移是否随赛道变化、`yaw` 的 `d±x.x` 是否随 final 变化（验证转向生效）、`x/z` 是否在移动。**任何"车不听话"的问题，先看这行日志定位，不要猜。**

## 13. 给下一个会话的建议

1. **遇"车不听话"先看 `[VCar]` 日志**：这是本项目最有效的调试手段。先确认是感知问题（final≈0）还是控制问题（yaw不变），再下手，不要盲调参。
2. **先确认丢失恢复**：看 `arrow_valid=False` 时车是否拐回赛道，微调 `arrow_lost_recover_gain` / `arrow_lost_default_dir`。
